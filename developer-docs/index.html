Developer Guide

Atelier 是怎样构建一个 Agent Harness 的

这是一份面向开发者和汇报场景的可浏览文档。它把当前代码拆成配置、Engine、工具、权限、存储、Skill、Memory、多 Agent 和前端等模块，说明每个模块负责什么、如何运行、如何修改。

阅读方式 每个主题都是独立页面，可以从左侧导航进入。每页都会标明对应代码文件、运行时流程、配置方式和当前边界。

项目定位

Atelier 不是普通聊天 UI。它是一个 Agent 运行时：模型可以调用工具，工具结果回到消息流，复杂任务可以写计划，可以排队，可以拆给子 Agent，状态可以通过 REST 和 WebSocket 被前端实时展示。

它的架构目标是把这些机制统一在一个可配置的框架内：同一套核心引擎服务 Web 和 CLI，同一套工具注册服务内置工具和 MCP 工具，同一套 session store 保存主会话和子会话。

核心代码地图

领域文件职责
入口api/rest.py, cli.py创建会话、发送消息、配置管理。
实时推送api/ws.py监听 token、message、state、event。
构建harness/factory.py创建 provider、工具、prompt、loop、engine。
运行时harness/engine/engine.py, harness/engine/loop.py状态管理与 ReAct 循环。
工具harness/tools/*工具 schema、注册、执行和内置工具。
存储harness/storage/*Session、Plan、Memory、Checkpoint。

当前实现边界

  • Memory 已经有工具写入、前端手动写入和自动召回，但没有候选记忆审批流。
  • TaskRecord 已经统一展示 plan、queue、subagent，但还不是持久 TaskStore。
  • Hook 已经接入 LLM 和工具调用前后，但没有覆盖所有生命周期点。
  • 前端是单文件应用，便于实验，但长期可以拆成组件。
