Configuration

配置系统

配置系统决定使用哪个模型、哪些工具可见、哪些工具需要审批、状态存在哪里、MCP 如何连接。

核心文件

  • config.yaml：项目主配置。
  • .env：本地密钥与 provider base url。
  • harness/config.py：解析配置并生成 dataclass。
  • api/rest.py：启动时加载配置，前端可通过 /config/yaml 编辑。

配置加载顺序

  1. 启动时 load_dotenv(override=False) 加载 .env。
  2. 优先读取 config.yaml。
  3. 如果没有 config.yaml，使用 HarnessConfig.from_env() 从环境变量构造最小配置。
  4. provider 名称会经过别名归一，例如 my-361api 会归一到 361api-openai。

Provider 配置

default_provider: openai-hub

providers:
  openai-hub:
    name: openai-compatible
    model: "${OPENAI_HUB_MODEL}"
    api_key: "${OPENAI_HUB_API_KEY}"
    base_url: "${OPENAI_HUB_BASE_URL}"
    max_tokens: 4096
    temperature: 0.0

name 决定 provider 类型。当前主要支持 openai-compatible 和 anthropic。

工具配置

tools:
  enabled:
    - read_file
    - write_file
    - edit_file
    - shell
    - memory
    - todo_write
  confirm_tools:
    - shell
    - powershell
  limits:
    shell: 15000
    memory: 8000

enabled 决定全局可注册工具。persona 还可以用 allowed_tools 做进一步收窄。

confirm_tools 决定哪些工具走审批 gate。是否真的弹审批还取决于当前 session 的 approval_mode。

存储配置

storage:
  backend: sqlite
  path: ./harness.db

当 backend 是 sqlite 时，Session、Memory、Plan 都使用同一个数据库文件。memory backend 主要适合测试和临时运行。

压缩配置

compression:
  token_window: 128000
  auto_trigger_ratio: 0.65
  micro_keep_recent: 6
  summary_provider: openai-hub-mini

压缩由 ContextCompressor 使用。summary_provider 可以指定一个便宜模型做摘要，避免主模型承担压缩成本。

MCP 配置

mcp_servers:
  filesystem:
    transport: stdio
    command: ["npx", "-y", "@modelcontextprotocol/server-filesystem", "."]

启动时 build_engine_with_mcp() 会连接 server，拉取工具 schema，并注册为 Harness 工具。

如何修改配置

  • 直接编辑 config.yaml。
  • 通过前端配置面板编辑 config.yaml，后端接口会先用 YAML parser 校验。
  • 修改 provider key/base_url 时通常只需要改 .env。
注意 修改配置后，已经创建的内存中 engine 不会自动重建。通常需要新建会话或重启服务，才能完整应用新 provider、工具和 MCP 配置。
