Web 前端

Web 前端不是单纯聊天框，它承担会话树、状态面板、审批卡片、任务视图、Memory 管理和实时事件展示。当前主要入口是 static/index.html。

1. 前端数据来源

来源用途
REST加载 session 列表、snapshot、配置、memory。
WebSocket接收 token、message、state、tool event 和 interrupt。
local state保存当前选中 session、展开节点、临时输入。

2. 会话树

会话树需要读取每个 session 的 parent_session_id。根 session 显示为主智能体，子 session 缩进显示，并允许继续嵌套。标题优先用自动命名 title，没有 title 时再退回 id 或创建时间。

3. 消息与状态

聊天区域展示 messages，状态区域展示 snapshot 中的 engine state。常见状态包括 idle、running、waiting interrupt、execution error。等待审批时，前端需要展示命令内容和允许用户 approve / reject。

4. Plan 和 Task UI

Task UI 应该从 snapshot 的 todos / tasks 读取，而不是从文本消息里解析。这样模型调用 todo_write 后，前端可以稳定展示结构化计划。

  • Plan item 显示步骤状态。
  • Pending command 显示审批状态。
  • Pending spawn 显示子智能体任务。
  • 队列项显示等待执行的用户输入。

5. 配置面板

配置面板用于选择 provider、model、approval mode、question mode 和 persona。会话内自由切换审批模式是前端的重要能力，因为同一个任务可能从只读分析进入写文件或 shell 执行阶段。

6. 常见前端问题

问题解释
/favicon.ico 404通常只是浏览器自动请求图标，不影响核心功能。
/sessions/.../state 404可能是 session id 不存在、子会话尚未刷新到前端，或接口路径和前端代码不一致。
新增子智能体不显示需要 WebSocket 推送 session list 更新，或创建后主动重新拉取 sessions。
Plan 不显示模型没有调用 todo_write，或前端没有渲染 snapshot.tasks。

7. 修改前端时的原则

前端应优先服务调试和操作效率。会话树、审批卡、任务列表和消息区要稳定，不要让动态文本撑坏布局。新增功能时尽量先确认后端 snapshot 是否已有结构化字段。
