Persistent Context

Memory

Memory 用来保存跨会话仍然有价值的信息，例如用户偏好、项目约定、长期事实。它不同于 messages，也不同于压缩摘要。

1. 当前何时添加 Memory

当前实现以工具写入为主。模型可以调用 memory 工具新增、搜索、列出、读取和删除记忆。系统不会把每一句对话都自动写成 memory。

动作说明
add写入一条长期记忆，通常需要模型判断该信息未来仍有用。
search根据查询文本检索相关记忆。
list列出当前可见记忆。
get读取某条记忆详情。
delete删除不再需要或错误的记忆。

2. 推理前如何召回

Engine 在进入主循环前，会根据最新用户输入检索 MemoryStore。召回结果会临时插入为系统上下文，让模型参考。循环结束前，这段临时 memory context 会从 messages 中移除，避免污染真实对话历史。

3. Memory、messages、summary 的区别

Messages

完整对话流水，表示用户和模型真实说过什么。

Summary

压缩后的上下文摘要，服务当前会话继续推理。

Memory

跨会话的长期事实，由工具写入并可被搜索召回。

4. 存储结构

SQLite 后端有 memories 表，通常包含 id、content、scope、metadata、created_at 等字段。内存后端提供相同接口，适合测试。

5. 前端管理

REST 层提供 /memory 相关接口，前端可以做成 Memory 管理面板。最小功能包括搜索、查看、删除和新增。后续可以加入标签、作用域、来源会话和置信度。

6. 当前仍需完善的地方

  • 自动写入策略还比较保守，需要更清晰的“什么时候值得记忆”。
  • 缺少独立的 memory 审批或用户确认策略。
  • 召回排序目前以简单搜索为主，后续可接 embedding 或更强的检索器。
