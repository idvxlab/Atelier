Subagents

多 Agent

多 Agent 机制让主智能体把探索性、并行性或隔离性任务分派给子智能体。每个子智能体本质上是一个独立 session，但通过 parent_session_id 和 pending_spawns 挂回父会话。

1. 创建流程

  1. 模型调用 spawn_agent 或 spawn_agents。
  2. 工具检查当前 persona 是否 can_spawn。
  3. 如果设置了 spawn_allowlist，继续校验目标 persona 是否允许。
  4. 系统创建子 session，写入 parent_session_id、origin、task 等 metadata。
  5. 父 Engine 增加 pending spawn，前端通过 snapshot / WebSocket 更新任务视图。

2. 为什么子智能体是 session

子智能体用 session 表示有两个好处：第一，它有自己的 messages、tools、provider 和审批状态；第二，它可以被前端直接打开查看，不需要把所有探索过程塞回父会话。

3. 树形会话关系

前端左侧会话树应按 parent_session_id 构造，而不是按创建时间平铺。这个结构必须支持多层嵌套，因为子智能体将来仍可能继续创建自己的子智能体。

实现提示 构建树时不要假设只有两层。先建立 id 到 node 的 map，再把每个 session 挂到它的 parent 下，找不到 parent 的作为根节点。

4. pending_spawns 的作用

pending_spawns 表示“父会话知道自己派出了哪些任务，但这些任务还没有被父会话消化”。它让主会话可以展示等待中的子任务，也为后续自动汇总结果留接口。

5. 最大深度与权限

当前 spawn_agent.py 中有最大深度限制，避免无限递归创建子会话。Persona 级权限进一步控制哪些角色可以 spawn、能 spawn 谁。
