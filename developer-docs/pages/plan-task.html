Planning Layer

Plan / Task

Plan 是模型自己维护的步骤清单，Task 是系统统一展示的任务视图。前者帮助推理过程有结构，后者把 todo、队列、子智能体等运行时工作统一呈现给用户。

1. PlanState 是什么

PlanState 表示当前会话的计划状态。它通常由 todo_write 写入，每个 item 有标题、状态、顺序、来源等信息。

  • pending：还没开始。
  • in_progress：当前正在处理。
  • completed：已经完成。

当前实现会把 plan 写入 storage 的 plans / plan_items，同时也同步到 session metadata，方便前端 snapshot 直接展示。

为了让计划真正约束执行，todo_write 会拒绝多个 in_progress。如果模型连续 3 轮工具调用没有更新计划，ReactLoop 会插入隐藏提醒，要求它更新 todo。

2. TaskRecord / TaskStatus 是什么

TaskRecord 是更宽的运行时任务模型，不只表示计划项。它把几个来源合成一个统一列表：

来源映射方式
Plan item来自 todo_write 的步骤，适合展示“模型打算做什么”。
Pending command等待审批或等待恢复的命令。
Pending spawn已创建但未汇报完成的子智能体任务。
Session queue会话排队中的用户输入或后续命令。

3. 模型怎么拆解任务

Atelier 不使用硬编码 planner 算法拆任务，而是通过 Prompt 和工具约束引导模型自己拆解：

  1. Prompt 组装层把 planning 指令注入系统消息，要求复杂任务先列步骤。
  2. 模型判断任务是否需要计划。如果需要，它调用 todo_write。
  3. todo_write 把步骤持久化，并通过 snapshot / WebSocket 推给前端。
  4. 主循环继续执行后续工具调用或文本输出。
  5. 步骤状态变化时，模型再次调用 todo_write 更新。

4. 为什么有时看不到 Plan

如果用户在输入里要求“做计划”，但模型没有调用 todo_write，前端就没有结构化 plan 可展示，只能看到普通文本回复。常见原因有三类：

  • Prompt 没有强制复杂任务必须调用 todo_write。
  • 当前 persona 的 allowed_tools 没有包含 todo 工具。
  • 前端只展示 messages，没有把 snapshot.tasks / todos 做成明显 UI。

当前系统已经有复杂任务提醒和多轮未更新提醒，但模型仍可能在简单任务里不建计划，这是正常的。

5. 前端应该怎么展示

推荐左侧会话树保留会话层级，右侧或侧栏提供独立任务面板。任务面板至少显示标题、状态、来源和所属 session。如果是子智能体生成的 plan，需要显示 parent_session_id，避免用户误以为新建了无关会话。

6. 和长期任务系统的区别

PlanState 偏向当前会话内的步骤管理。TaskRecord 可以逐步扩展成长期任务图，但如果要支持跨会话任务，需要补充全局 task id、依赖关系、负责人和恢复策略。
