权限与审批

权限系统回答三个问题：模型能看见哪些工具，哪些工具需要审批，当前会话如何处理审批。

工具可见性

全局工具可见性由 config.yaml 控制：

tools:
  enabled:
    - read_file
    - shell
    - memory
    - todo_write

persona 可以再通过 allowed_tools 收窄工具范围。最终注册工具是：

global enabled ∩ persona allowed_tools

如果 persona 没有设置 allowed_tools，就使用全局 enabled。

confirm_tools

confirm_tools 决定哪些工具属于高风险工具。

confirm_tools:
  - shell
  - powershell

当模型调用这些工具时，Engine 会进入 confirmation gate。前端看到 WAITING_CONFIRMATION 后展示审批面板。

approval_mode

模式行为
ask命中 confirm_tools 时等待用户批准或拒绝。
auto自动批准高风险工具，但仍记录事件。
full绕过 confirm_tools gate，当前会话全权限运行。

运行时可以通过 PATCH /sessions/{id}/approval-mode 切换。

persona 默认审批模式

persona frontmatter 可以设置：

default_approval_mode: ask

创建会话时，如果请求没有明确传入 approval_mode，后端会读取 persona 的默认值。子 Agent 创建时也会应用子 AgentProfile 的默认审批模式；没有默认值时继承父 Agent 的审批模式。

审批执行路径

  1. ReactLoop 准备执行工具前调用 on_pre_execute。
  2. AgentEngine 的 _confirmation_gate() 检查工具名是否在 confirm_tools。
  3. 如果 approval_mode 是 full，直接放行。
  4. 如果 approval_mode 是 auto，自动放行并记录事件。
  5. 如果 approval_mode 是 ask，状态转为 WAITING_CONFIRMATION。
  6. 用户点击允许时调用 /confirm，点击拒绝时调用 /deny。
  7. 拒绝会抛出 CancelledError，Engine 回到 WAITING_INPUT。

多 Agent 权限

AgentProfile 支持：

can_spawn: true
spawn_allowlist:
  - reviewer
  - docs-writer

spawn_agent 真正创建子 Agent 前会检查父 AgentProfile。如果 can_spawn: false，直接返回错误。如果有 allowlist，只能创建列表中的 agent。

边界 当前权限还不是操作系统级沙箱。它控制的是模型工具可见性、审批 gate 和 agent 调度规则。真实文件系统安全还需要依赖工具实现和运行环境约束。
