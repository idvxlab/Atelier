Knowledge Injection

Skill 机制

Skill 用来给智能体提供额外能力说明。Atelier 的设计是“先注入描述，必要时再加载全文”，避免一开始就把大量文档塞进上下文。

1. 扫描与注册

SkillRegistry 会扫描多个目录，把每个 Skill 的元信息注册成可检索对象。典型来源包括项目目录、用户目录，以及兼容 Claude 风格的 skill 目录。

  • .myharness/skills：项目级 Skill。
  • ~/.myharness/skills：用户级 Skill。
  • .claude/skills 和 ~/.claude/skills：兼容已有资料。

2. Prompt 中默认注入什么

默认不会注入整个 Skill 文件。系统会把 Skill 名称、描述、触发条件等轻量信息放入 Prompt，让模型知道“有哪些能力可以申请使用”。

这样做的影响 Prompt 更短，模型选择 Skill 的成本更低，但如果描述太宽泛，模型可能频繁调用 use_skill。

3. use_skill 如何加载全文

  1. 模型看到 Skill 摘要后，决定调用 use_skill。
  2. ToolExecutor 执行该工具，Registry 根据 skill 名称找到文件。
  3. 系统读取 Skill 正文，并把内容作为工具结果返回给模型。
  4. 模型在下一轮推理中使用全文说明完成任务。

4. 频繁调用 Skill 的原因

如果模型频繁 use_skill，通常不是工具层错误，而是 Prompt 策略过于鼓励“先读 Skill”。可从三处调整：

位置调整方式
Skill 描述写清使用边界，例如“仅在需要修改前端视觉层时使用”。
系统提示词要求模型先判断任务是否真的需要额外知识。
工具策略为 use_skill 增加 hook 或计数限制，避免同一轮反复读取。

5. 写 Skill 的推荐结构

一个好 Skill 应该包含触发条件、禁用场景、执行步骤和少量关键约束。不要把长期项目状态写进 Skill，那类内容更适合 Memory 或项目文档。

6. 和 Persona 的区别

Persona 是“这个智能体是谁”，Skill 是“遇到某类任务时可以临时加载的能力”。Persona 常驻 Prompt，Skill 按需加载。
