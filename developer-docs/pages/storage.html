State & Persistence

状态与存储

存储层负责让会话、计划、记忆和压缩前原文在重启后仍能恢复。MyHarness 当前以 SQLite 为主，同时保留内存后端用于测试。

1. 存储对象

对象文件作用
SessionStoreharness/storage/session.py保存会话 messages 和 metadata。
CheckpointStoreharness/storage/checkpoint.py保存运行中某轮状态快照。
MemoryStoreharness/storage/memory_store.py保存跨会话长期记忆。
PlanStoreharness/storage/plan_store.py保存会话计划和计划项。
Transcript.myharness/transcripts/<session_id>保存 auto compact 前的完整原始消息。

2. SQLite 表

SQLite 后端位于 harness/storage/backends/sqlite.py。默认数据库路径来自 config.yaml 的 storage.path。

表保存内容
sessionssession id、messages JSON、metadata、display_name、pin/archive 等状态。
checkpointscheckpoint id、session id、round index、EngineState、messages。
memories长期记忆 content、scope、tags、source session、metadata。
plansplan id、session id、title、status。
plan_items计划项内容、状态、绑定的子 session、结果 message id。

3. 上下文压缩与 transcript

ContextCompressor 有两层：micro 会清理较旧工具结果正文，auto 会调用 summarizer，把旧消息压缩成摘要，并重注入身份和任务目标。

触发 auto compact 前，系统会先把完整 messages 写入 JSONL transcript。默认路径是 .myharness/transcripts/<session_id>/round_*.jsonl。这解决了一个关键问题：摘要如果漏信息，仍然能回查压缩前原文。

4. session metadata

metadata 是把多个机制串起来的轻量状态层。常见字段包括：

  • provider、persona、question_mode、approval_mode
  • title、display_name
  • parent_session_id、spawn_depth
  • plan_item_id

5. 恢复流程

  1. 前端请求 /sessions/{id}/state。
  2. 如果 engine 不在内存，REST 层从 SessionStore 加载 session。
  3. 根据 metadata 选择 provider、persona、question mode 和 approval mode。
  4. 调用 _build_session_engine() 重新创建 Engine。
  5. engine.restore_from_store() 把 messages 放回 Engine。
  6. 返回 snapshot 给前端渲染。
开发提示 新增持久化对象时要同时考虑内存后端、SQLite 后端、REST snapshot 和前端展示。transcript 当前是文件归档，不走 SQLite。
