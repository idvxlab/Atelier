工具系统

工具系统负责把模型的 tool call 路由成真实动作，然后把结果包装回 tool_result。

三层结构

层文件说明
类型harness/types/tools.py定义 ToolSchema、ToolParam、ToolResult。
注册harness/tools/registry.py维护工具名到 schema/handler 的映射。
执行harness/tools/executor.py并发执行工具、捕获错误、截断输出、处理 interrupt。

工具注册来源

核心注册表在 harness/factory.py 的 ALL_TOOLS。构建 Engine 时会按以下规则加载：

  1. 读取 config.tools.enabled。
  2. 如果 persona 有 allowed_tools，取它和全局 enabled 的交集。
  3. 对 todo_write、memory 这类需要运行时 store 的工具，用工厂函数闭包绑定当前 session。
  4. background_task 用于长命令的 start/status/list/cancel，适合测试、安装和构建。
  5. 如果存在 skills，额外注册 use_skill。
  6. 如果当前 spawn 深度未超限，注册 spawn_agent 和 spawn_agents。
  7. 如果启用了 MCP，MCP 工具也会注册进同一个 ToolRegistry。

ToolExecutor 做了什么

  • 并发执行同一轮里的多个 tool call。
  • 如果工具不存在，返回 error tool_result。
  • 如果 handler 抛异常，捕获并包装为错误内容。
  • 如果 handler 接受 _tool_call_id，自动传入 tool call id，ask_user 用它定位后续 rewrite。
  • 如果结果过长，写入 OverflowStore 并返回引用。
  • 如果结果是 interruptible，保留 is_interrupt=True。
  • 触发 before/after tool hook。

新增工具流程

  1. 新建 harness/tools/builtin/my_tool.py。
  2. 定义 MY_TOOL_SCHEMA。
  3. 实现 async def my_tool(...)。
  4. 在 harness/tools/builtin/__init__.py 导出。
  5. 在 harness/factory.py 的 ALL_TOOLS 注册。
  6. 在 config.yaml tools.enabled 启用。
  7. 需要审批时加入 tools.confirm_tools。
  8. 补 tests/test_tools.py。
MY_TOOL_SCHEMA = ToolSchema(
    name="my_tool",
    description="Do one clear thing.",
    params=[
        ToolParam(name="path", type="string", description="Target path"),
    ],
)

async def my_tool(path: str) -> str:
    try:
        return "ok"
    except Exception as exc:
        return f"Error: {exc}"
设计原则 工具 handler 尽量返回字符串。错误也返回 Error: ...，这样模型能根据错误继续恢复，而不是让主循环崩掉。
